## PLAN

### recommended_order
MIGRATE quasiisothermaldf (Pdf.4) FIRST, then diskdf (Pdf.1); evolveddiskdf (Pdf.3) is a reject-guard-only PR that is independent of both and can land anytime.

Rationale — qdf before diskdf (higher value AND lower risk):
- HIGHER VALUE: qdf is the action-based workhorse and its DF-eval path (__call__ L230 -> self._aA.__call__ ACTIONS only, then pure arithmetic in _func L254-258) is a clean autodiff surface — exactly the point of the backend project. It leverages the JUST-MERGED #131 Staeckel action gradients (actions+grads DONE for Staeckel/Adiabatic/Isochrone); diskdf's AD value is its _dlnfd* grads but they sit behind a design-level blocker.
- LOWER RISK: qdf needs NO novel primitive. Every hazard maps onto a READY backend (Spline1D for _rgInterp, nested/fixed_quad for surfacemass_z, and potential.rl is ALREADY backend-migrated -> the _rg out-of-range fallback is backend-ready, closing the one 'VERIFY' hazard). diskdf must BUILD a new backend-aware complex-capable _scimath_log (numpy.lib.scimath.log has no jax/torch analog) that, if wrong, silently corrupts cold/sigma->0 DF values across ~30 sites and breaks the whole cold-* test block. Landing qdf first ships the 'standard migration kit' (where-masking, ndim dispatch, GL tiling, Spline1D, xp ufuncs) + the per-module test-file scaffolding, so diskdf's genuinely-novel scimath design piece is tackled with the pattern established.
- No ordering pressure from the evolveddiskdf->diskdf(initdf) dependency, because evolveddiskdf is reject-guard-only this wave regardless of diskdf's Pdf.1 status.

No cross-family base PR is required: the only new shared helper (_scimath_log) is diskdf-only and lands inside Pdf.1's first PR; quad/interp/optimize/special primitives already exist and are READY.

### top_risks
1. (diskdf, blocker) _scimath_log fidelity: a real-only xp.log silently returns NaN for negative reals where the code relies on scimath's complex log|x|+i*pi (log(L/xE-1), cold/sigma->0 DFs), corrupting the entire cold-* test block; the downstream xp.real strip must be preserved and both xp.where dead branches guarded. 2. (both) Byte-identity of sentinel where-masking replacing numpy fancy-assign at degenerate/near-turning-point inputs — qdf __call__ NaN/cutcounter (L283-305), diskdf axipotential (L3085-3092) and shudf xL<0 (L2322). Mirror the raw-mask / NaN-free-value-branch idiom exactly.

4. (qdf) GL-tiling reshape/broadcast byte-order across the 7 repeated blocks (numpy.tile/reshape -> xp.broadcast/reshape) — voluminous, mechanical, ordering-sensitive.
5. (qdf) Staeckel action GL floor at vz/z turning points (staeckel-action-quadrature-C-parity) -> the high-|z| gl staeckel moments are tolerance-thin.
6. (both) device-anchoring of leggauss nodes x sigma(R): CPU/CUDA mismatch is latent (CI has no GPU) -> must GPU-verify PR-4b/PR-1b.
7. (evolveddiskdf) over-scoping into an Orbit-integration rabbit hole: a backend orbit integrator now exists (diffrax/torchdiffeq, test_backend_orbit_integrate.py) but is single-orbit/3D-only, so the many-planar-orbit grid path still can't use it, and initdf is a numpy dehnendf (Pdf.1).
