## 7. PATTERN NOTE for the variant fan-out (constantbeta/osipkovmerritt/eddington/king/Plummer/NFW/PowerLaw)
- **Dispatch:** `xp = _resolve_xp(<data args>)` (import from `.sphericaldf`), then `if xp is numpy: <literal old code>` + backend branch. Never bare `get_namespace(x)` — user inputs include **lists** (crashes array_api_compat) and the data-guard-`else numpy` variant recreates the hollow-green island. For construction-time code with scalar inputs use bare `get_namespace()` (context/forced only).
- **Coerce before potentials:** undecorated `_evaluatePotentials`/`_rforce` reject numpy/float coords under forced **torch** — `xp.asarray(x) * 1.0` every coordinate on the backend branch (this bit me in `_vmax_at_r`, `_p_v_at_r`, `_handle_rmin`, `phi_at_zero`, `_RToxi(rmin/rmax)`). Same for `xp.atleast_1d`/`xp.sqrt` on possible Python scalars (torch rejects them; jax doesn't — test torch!).
- **fE variants:** replicate the pilot's functional out-of-bounds handling (`dead`-mask → in-domain dummy → compute → `xp.where(dead, 0, fE)`), and **hunt the numpy `numpy.where(cond)[0]` row-quirk**: for 2-D grids the numpy path zeroes whole *rows*, which currently masks genuine 0/0 edges (Hernquist fE(Etilde==0) is NaN in 1-D numpy). Guard each variant's exact boundary edges (E→0, E→Φ(0), Q<0 for OM, Etilde==1) elementwise on the backend branch; expect fp-level draw differences via the icdf `start/end_indx` float-== index selection if you don't (that mechanism amplified a 1e-17 NaN into 0.65-scale velocity-draw corruption before the edge guard).
- **Quadrature recipes (all validated here):** v-moment → `fixed_quad(xp, ..., 0, vmax(r), n=100)` with `Phi(r)[..., None]` broadcast (node axis trails; array-r works out of the box). dMdE-type ∫₀^{rphi} with sqrt turning point → substitute `r = rphi − s²` then plain GL (beats adaptive scipy by 7 orders). Nested (v,η)/(r,L) → `nested_quad` with **manually pre-broadcast limits** `b[..., None, None]` (vector limits otherwise land on the wrong axis), inner sqrt endpoint via `t = Lmax sinφ`. Call `self._call_internal(E, L, Lz)` directly in backend integrands — `self(...)`'s reshape logic breaks on broadcast grids.
- **Interpolators:** `_setup_rphi_interpolator`/`_make_cmf_interpolator` now return `Spline1D` (numpy queries byte-identical scipy, backend queries native/differentiable) — variants' `self._rphi(tE)` calls need no change. **Do NOT wrap `_make_pvr_interpolator`'s RectBivariateSpline** — tests call `.get_knots()` on it (kept scipy; grid *construction* is backend-vectorized then `_as_numpy`-pulled). eddington's `_fE_interp` and constantbeta's `_logstartt` will hit the same constraint — check test pokes before wrapping.
- **Sampling contract:** numpy RNG untouched; convert at boundaries with `_as_numpy` (handles torch detach/CPU; `[()]` for 0-d inputs so backend scalars behave like floats); deterministic DF/mass grid evals run vectorized on the forced backend then pull numpy. `_ensure_fE_interp`-style init loops (eddington's 10001-point `phis`, constantbeta's jax-grad tables) are the remaining forced-mode slow spots — the vectorized-`phis` branch in `_setup_rphi_interpolator` shows the pattern.
- **Weak scalars:** constant gamma-factors stay `scipy.special.gamma` (Python-int args, weak-scalar multiply is safe for torch f32); variants with gamma/hyp2f1 *of E-dependent args* (constantbeta, PowerLaw) must route through `galpy.backend.special` (the pilot needed none). Resolve `xp` including stored DF constants (`_resolve_xp(Ei, self._psi0)`) so backend-built potentials keep parameter grads.
